# 电阻器质量系统 · APQP / FMEA / SPC / MSA / PPAP

当前应用版本：**1.3.0**（关联文件预览台、手动复制编制、受控修订、质量工具穿透与 MSA 来源修正）。

一套可运行的本地质量管理系统，覆盖 **APQP → DFMEA/PFMEA → PFD → 控制计划 → SPC/MSA → PPAP → 基线冻结** 的全流程。
数据模型与《07 数据字典》同源，业务规则依据 AIAG-VDA FMEA 手册（2019）、IATF 16949、PPAP 第 4 版与 MSA 第 4 版。

---

## 启动

```bash
# 需要 Node.js ≥ 22.5（使用内置 node:sqlite，零第三方依赖）
cd resistor-qms
node server.js
```

打开 **http://127.0.0.1:8848** 。首次启动会自动建库并写入一套「RJ 系列 1/4W 金属膜电阻器」的演示数据。

- 端口可用环境变量覆盖：`PORT=9000 node server.js`
- 数据库文件：`data/qms.db`（WAL 模式）。删除该文件后重启即可恢复初始演示数据。

## 技术选型

| 层 | 选择 | 原因 |
|---|---|---|
| 运行时 | Node.js 24（内置 `node:sqlite`） | 零依赖、无构建步骤，`git clone` 即可跑 |
| 存储 | SQLite（38 张业务与治理表） | 真落库、可 JOIN、可迁移到 PostgreSQL |
| 服务端 | 原生 `http` + 轻量路由 | 无框架负担，路由与业务逻辑清晰可读 |
| 前端 | 原生 JS 单页 + 手写 SVG 图表 | 无构建、离线可用，控制图不依赖图表库 |

## 从示意图生成 DFMEA 结构树

FMEA 页不是「一棵树 + 一张表」，而是**一张按结构组织的工作表**：每个结构节点是一行表头（名称 + 功能 + 已分析条数），下面直接挂该结构的失效分析行。没有分析的结构会显示「该结构尚未做失效分析」——**缺口一眼可见**，这正是 FMEA 评审要看的。

工程师最容易卡在「结构分析」这一步：知道产品长什么样，但拆不出「总成 → 组件 → 零件」。

DFMEA 页有 **从示意图生成结构** 按钮：粘贴一张带标注的剖面图，系统识别图上的零件名，自动生成三级结构树，并给每个零件配上功能建议与失效候选。

生成结果会显示在 DFMEA 页的 **结构树** 卡片里（15–20 个节点），每个节点可以直接「AI 分析」或「＋分析行」。
**重复导入会自动替换**上一次由示意图生成的整棵树，不会叠加。

### AI 辅助（可接外部接口）

**入口在「分析行」编辑弹窗里，不在结构树上**：结构树每个节点只有「＋分析行」，点开就是行编辑弹窗，弹窗顶部是「AI 分析」。

**功能（Function）也有 AI**：每个结构节点右侧的「AI 功能」，可以填一句大白话（如"撑住电阻膜，不导电，还要能扛装配时引脚的压力"），AI 归拢成 FMEA 手册口径：

> 承载金属膜层，绝缘电阻 ≥10¹⁰ Ω
> 承受引脚压装轴向力 ≥50 N 不变形
> 传导膜层热量，热导率 ≥20 W/(m·K)

提示词里锁死了四条规则：动词+宾语+可测量要求、不许出现「质量好/可靠」、不超过 35 字、只写该零件自身功能。功能不写对，后面的失效分析全是歪的，所以这一步比失效更值得让 AI 帮忙。

流程：

1. 点「AI 分析」→ 按该行关联的结构节点生成 3–5 条**候选失效**（失效影响 / 失效模式 / 失效原因 / S）
2. 每条候选的三个文本框**可直接改**，改完点「采用」填进下方表单
3. 检查 O/D 后点「保存分析行」才真正写库

这样设计的原因：AI 给的是草稿，工程师才是签字的人。**采用 ≠ 保存**，中间必须有人看一眼。

- FE/FM/FC 是**可输入可选择**的组合框：既能挑已有的，也能直接写新的（写新会自动建节点，同名自动复用，不会刷出一堆重复节点）
- 兼容 **OpenAI 协议**的任意端点：OpenAI / DeepSeek / 通义 / 本地 vLLM / Ollama
- 设置页有**服务商预设**和**测试连接**，会明确告诉你是「网络不通 / Key 无效 / 路径不对 / 模型不存在」
- **未配置时退回本地规则**，仍能给出通用建议，并标注来源（本地规则 / 外部 AI）
- AI 只产出候选：生成行后 O/D 默认 5/5，必须按实际控制措施重评 —— 审核必查点，系统不替你判定

**OCR 部分全部本地完成，不调用任何外部服务**：

| 步骤 | 技术 | 说明 |
|---|---|---|
| 读图 | Windows.Media.Ocr（离线，zh-Hans-CN） | 逐字返回包围盒，不是整行文本 |
| 切分 | 行聚类 + 间距切分 + 制品词典最长匹配 | 「白瓷棒膜层」在图上只隔 4px，纯靠间距会切错；词典里有 30+ 电阻器结构词 |
| 归类 | 关键词规则（基体/膜层/保护层/引出端/结构特征） | 归到 5 类，未知词进「其他零件」 |
| 建树 | 语义层级 + 单节点压平 | 「电阻膜层→膜层」压成一层，「引出端→引线帽」保留两层 |
| 写库 | 生成 `fmea_node` 结构节点 + 示意图存档 | 图片与识别出的标签一并存，供审核追溯 |

实测效果（用仓库里 `public/samples/resistor-drawing.png`）：

```
OCR 原始输出：白瓷棒膜层清漆缓冲层螺旋槽塑封层引线帽
切分结果：白瓷棒 | 膜层 | 清漆 | 缓冲层 | 塑封层 | 引线帽 | 螺旋槽

生成结构：
  电阻芯体（承载电阻体并决定阻值）
    ├ 白瓷棒   —— 提供机械支撑与电气绝缘，是膜层的载体
    └ 螺旋槽   —— 调整有效导电截面，实现阻值微调（调阻）
  膜层        —— 形成电阻体，单位面积电阻（方阻）决定阻值
  保护层（隔离环境，保证耐压与长期稳定性）
    ├ 清漆     —— 提供层间绝缘与防潮
    ├ 缓冲层   —— 吸收热应力与机械应力，防止涂层开裂
    └ 塑封层   —— 提供机械保护与环境隔离
  引出端（实现电气连接与机械固定）
    └ 引线帽   —— 实现端头电气连接与机械固定
```

识别结果在写入前会以**可编辑标签**呈现：可以删掉误识别的字、补上漏掉的零件、改名后再生成。**不做「AI 一把梭」**——结构是 FMEA 的地基，必须让人确认一遍。

限制：只认印刷体中文标注（手写体准确率低）；引线/箭头不会被识别为关系，层级靠规则推断，复杂产品需要在预览里手工调整。

## 上传自己的模板（.xlsx / .docx）

预置的 49 个表单结构只是"够用"，真正的落地一定是把贵司已有的表格搬进来。APQP 阶段页每个阶段都有 **上传到本阶段**，可把上传模板绑定到原交付物编号，并配置“单元格 → 业务字段”映射；同一编号只能绑定一个模板。

**流程**：选文件 → 选归属阶段 → 上传解析 → 直接进入编辑器（可继续修改）→ 下载回 Excel/Word。

**解析做了什么**（`lib/parse.js` + `lib/infer.js`，全部手工实现，无第三方库）：

| 步骤 | 处理 |
|---|---|
| 解包 | 自写 ZIP 读取（中央目录 + `zlib.inflateRawSync`） |
| 解析 | 自写容错 XML 解析器，取 `sheetData` / `mergeCells` / `cols` / `styles` |
| 合并单元格 | 保留 colspan/rowspan，编辑时与原表版式一致 |
| 表头识别 | 要求「连续 ≥3 列 + 列名简短 + 无粗体混排」；分组表头（合并行）会被跳过 |
| 字段识别 | 左侧标签 + 右侧空白（含 `＿＿＿`、`—` 等占位符）→ 识别为单项字段 |
| 空白判定 | 只要不含文字/数字/汉字即视为未填写，兼容各种占位符 |
| Word 文档 | 按段落与表格还原，`标签：值` 形式自动转成字段 |

**填写说明怎么来的**：一套按列名/标签语义匹配的规则引擎（`lib/infer.js` 的 `RULES`），覆盖日期、编号、版本、数量、百分比、责任人、判定、备注、工序、特性、参数、设备、材料、客户、阶段、原因、措施等 20 类语义；匹配不到时给通用说明。**不是大模型生成**，所以稳定、可解释、可自己加规则。

说明的呈现方式有两种：右侧「填写说明」面板按「表格 x」与「单项字段」分组列出；输入框内的灰色提示则只显示该列的说明。

**限制**：只支持 Office Open XML（`.xlsx` / `.docx`），旧版 `.xls` / `.doc` 需先另存；复杂嵌套表、跨页公式、图片与条件格式不会保留（只保留值、合并、列宽、粗体）。

## 演示脚本（约 5 分钟）

1. **APQP 交付物** — 六个阶段共 68 个目录项（49 表单 + 9 模块 + 10 输入/活动）；点「P1-07 设计目标」→ 编辑 → 提交/批准 → 下载 Word，确认能用 Word 打开。
2. **概览看板** — 看风险与缺口：高 AP 未决策、CP 未生成监控项、检具待复评。
2. **特性穿透** — 选「阻值精度 CHR-D-0142」，看它由 5 个过程特性共同保证，并下钻到 CP 与监控项。
3. **FMEA 七步法** — 点开 `FR-DF-00004`（耐压，S=10）：改 O 值，观察 AP 实时变化；
   查看它的「处置决定」——演示 S=10 且 O≥4 时，改善探测无法降低 AP。
4. **控制计划** — 点「一键自动映射」，看新增/更新/跳过人工覆盖各多少行。
5. **SPC** — `MON-0001 阻值精度` Cpk=1.75（达标）；切到 `MON-0002 成膜厚度` Cpk≈0.58（应报警）。
6. **PPAP** — 点「冻结基线并打包」，得到清单哈希；去「基线与变更」对比两个基线。

## 与文档交付物的一致性

| 文档结论 | 系统中的落点 |
|---|---|
| 特性关联必须是 M:N | `char_link` 表 + 穿透链视图 |
| 一行 = 一个 (FE, FM, FC) | `fmea_row` 唯一组合；同 FE 下 S 强制一致（服务端校验） |
| AP 是查表不是相乘 | `ap_matrix` 1000 行 + 后端查表；前端仅做实时预览 |
| AP=高强制「决定」而非「措施」 | `fmea_decision`：决定/理由/批准人/复审日期 |
| CP 特性只读、存 ID | `cp_row.char_id` 外键，界面不可编辑 |
| 抽样必须结构化 | `sample_size / freq_value / freq_unit / freq_trigger` 四列 |
| 基线是不可变快照 | `baseline` + `baseline_item.snapshot`（JSON）+ 逐对象哈希 |
| Cpk 用分选前数据 | `monitoring_item.before_sort` 字段（二期 SPC 导入时使用） |

## API 速查

所有接口在 `/api` 下，返回 JSON。主要端点：

```
GET  /api/docs                   68 个交付物/模块/活动/输入清单（完成度只统计表单类）
GET  /api/docs/:code             单份模板结构与当前内容
PUT  /api/docs/:code             保存内容（自动判定状态与完成度）
GET  /api/docs/:code/export?fmt=docx|xlsx   导出真实 Office 文件
GET  /api/dashboard              看板汇总
GET  /api/chars/:id              特性穿透链
GET  /api/fmea?type=DFMEA|PFMEA  七步法结构与分析行
POST /api/fmea/row               新增/更新分析行（校验 S 一致性）
POST /api/fmea/decision          登记 AP=H 处置决定
POST /api/cp/generate            CP 自动映射（幂等）
PATCH /api/cp/row/:id            修改抽样/反应计划（自动打 override 标记）
GET  /api/spc/:monId             SPC 明细
POST /api/spc/:monId             导入子组数据并重算
POST /api/msa                    计算 GR&R
PATCH /api/ppap/:no              更新 PPAP 要素
POST /api/baselines              冻结基线
GET  /api/baselines/diff?a=&b=   两个基线差异对比
```

## 已知边界（这是演示系统，不是生产系统）

- **带登录与岗位权限**：18 个角色（管理员 / 总经理 / 总工 / 管理者代表 / 4 位副总 / 质量 / 工艺 / 设计 / 生产 / 检验 / 采购 / 市场 / 标准化 / 综合只读 / 内审），交付物按目录归属校验编制岗位，副总只能批本板块。默认只监听 127.0.0.1；`--lan` 会以明文 HTTP 暴露到局域网，需自行加 TLS 与项目成员配置。首次启动生成的一次性口令写在 `data/initial-credentials.<库名>.txt`，首次登录强制修改。
- **AP 矩阵已改为数据库查表**，并支持“批量校对 + 活动批准”；初始矩阵仍按公开资料整理，正式使用前须按 AIAG-VDA 手册原表逐孔校对。
- SPC 已实现超限、连续 7 点单侧、连续 6 点趋势、14 点交替、2/3 与 4/5 区域规则、15 点集中、8 点分散等常用判异；控制图当前仍只绘制 Xbar-R。
- GR&R 使用均值-极差法，支持动态零件/评价人/试验次数，但未实现 ANOVA 法、偏倚、线性和稳定性研究。
- PPAP 打包已生成真实 ZIP，包含真实清单、基线对象 JSON、逐文件 SHA-256 和 ZIP 哈希。
- **项目成员默认是兼容模式**（未配置成员时全员可见）。多部门共用时设 `QMS_STRICT_MEMBERS=1`：此时只有成员和管理层 / 内审可见，未配置成员的项目要先在「项目成员」里加人。
- 备份包含数据库与附件（`backups/<名称>-attachments/`），自动保留最近 10 份；登录连续失败 5 次锁定 5 分钟。
- 未接入 ERP/MES；批次与物料追溯为占位字段。
- 交付物已支持提交、批准、退回和版本历史，但仍不含 CA 电子签名与受控发放流程；客户模板已支持上传、绑定和简单业务字段映射，不完整保留公式、图片、条件格式和复杂样式。
