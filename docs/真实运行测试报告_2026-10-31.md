## 3. 已发现问题

### BUG-001：交付物页面标题出现 `[object Object]`

**优先级：中**

**复现步骤：**

1. 打开 APQP → 阶段管理。
2. 找到 P1-07“设计目标”。
3. 点击“编辑”。
4. 查看页面顶部标题和信息行。

**实际结果：**

页面显示：

```text
P1-07 · [object Object]
[object Object] · 设计 · 版本 V1.0 · 更新于 ...
```

**预期结果：**

应显示交付物名称，例如：

```text
P1-07 · 设计目标
设计目标 · 设计 · 版本 V1.0 · 更新于 ...
```

**影响：**

不影响保存和导出，但会降低用户对当前文档的识别能力，也会影响审计截图和交付文档的专业性。

**建议：**

检查前端渲染交付物名称的字段类型。当前很可能把对象直接插入模板字符串，应改为使用名称字段，例如 `doc.title`、`doc.name` 或后端返回的标准化名称字段。

### BUG-002：保存完成的交付物刷新后状态回到“草稿”

**优先级：中，需确认业务规则**

**复现步骤：**

1. 打开 P1-07“设计目标”。
2. 修改“编制”为“测试编制人”。
3. 点击“保存”。
4. 页面提示“已保存（完成度 100%）”。
5. 刷新页面。

**实际结果：**

刷新前页面状态显示“已完成”；刷新后状态显示“草稿”，并出现“提交审核”按钮。

**预期结果：**

如果“已完成”表示表单完成度，状态应保持一致；如果保存后必须重新进入审核，则页面应明确提示“已保存为草稿，需提交审核”，避免用户误以为完成状态已经提交。

**建议：**

统一“完成度”和“文档状态”的定义，并在保存接口及前端提示中明确区分：

- 表单字段已填写完成；
- 文档已提交审核；
- 文档已批准/发布。

2. 明确 BUG-002 的状态机规则，补充“保存、提交审核、批准、退回”的状态验收用例。
3. 对 PFD → PFMEA → CP → SPC 的自动映射做一轮数据变更回归测试。
4. 对 PPAP 冻结基线、ZIP 哈希校验和下载文件打开性做正式验收。
5. 使用真实模板分别验证 `.xlsx` 和 `.docx` 的合并单元格、日期、数字和中文内容。
