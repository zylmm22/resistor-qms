## 本模块结论

- **ECR 目前是“带快照的变更登记”，不是变更实施**：`/apply` 只把状态改为“已实施”并冻结一份全项目基线，不修改任何受控对象；变更内容与受影响对象的“实际修改”之间没有连接。
- **特性字典是穿透主线的源头**，但删除/修改的引用保护不完整，且 `P2-11` 同步只写文本不写规范上下限，导致下游 SPC/MSA 拿不到规范。
- **新增特性抽屉存在确定性前端错误**（`ReferenceError`），入口直接不可用。

## 工程变更（ECR）

### E-01 【中】【逻辑】“实施”不修改任何对象，只是冻结一份快照

- **位置**：`server.js:7181-7210`
- **现象**：`/api/ecr/:id/apply` 校验状态为“已批准”后：更新 ECR 状态为“已实施”、调用 `DB.freezeBaseline(CUR, 'ECR … 实施快照', 'ECR-<id>', …)`、写一条审批记录，**没有任何数据变更**。
- **触发/影响**：用户以为“实施变更”会把图纸/特性/CP/FMEA 改成新状态，实际只是多了一个基线；后续仍需手工逐模块修改，且修改后没有人把这些改动与 ECR 关联。关闭 ECR 只要求存在分支基线，无法证明变更真的落地。
- **建议**：把 ECR 的 `payload` 变成结构化的变更项（对象类型/对象 ID/字段/旧值/新值），`/apply` 在事务中逐项应用并产生“变更后基线”；或在 UI 明确标注“本操作仅登记，不修改数据”，并提供“执行变更”清单。

### E-02 【中】【安全】ECR 的申请人与批准人来自请求体

- **位置**：`server.js:7135`（`L.audit(body.requested_by || '张工艺', …)`）、`server.js:7165-7177`（`approved_by = body.approved_by`，审计同样取 body）；`public/app.js:921/948/956`（硬编码“质量经理 王”）
- **现象**：任何调用方可指定申请人/批准人；前端默认值写死。
- **建议**：取会话用户；批准需角色校验且禁止申请人自批（同 S-03/S-04）。

### E-03 【中】【逻辑】ECR 状态迁移缺少完整性校验

- **位置**：`server.js:7152-7179`
- **现象**：只拦“未实施不能关闭”“已实施需通过 apply”；没有校验“已批准必须有影响分析”“关闭必须有验证结论/措施完成”。
- **建议**：状态机加前置条件（影响分析完成、验证证据、关联对象已更新）；每次迁移写审计与原因。

### E-04 【低】【页面】ECR 影响分析展示有限

- **位置**：`public/app.js:870-976`；`server.js:7138-7150`
- **现象**：接口返回 `items` 与 `branchBaseline`，页面主要展示列表与状态；没有“变更前/后对比”“受影响交付物清单”“未完成项”。
- **建议**：以影响分析为核心重构 ECR 详情页；提供基线 diff 入口。

## 特性字典与穿透

### D-01 【高】【操作】新增特性抽屉因 `ReferenceError` 无法打开

- **位置**：`public/app.js:8220-8264`（`#charSourceRefs` 渲染函数引用函数内 `const`）；`public/app.js:8122`（`sourceList` 定义位置）
- **现象**：抽屉渲染时访问了作用域外的变量，抛 `ReferenceError`，抽屉打不开或内容为空。
- **触发/影响**：无法新增特性；演示时直接卡住主线起点。
- **建议**：把 `sourceList` 提升为模块级/参数传入；补一条“打开新增特性抽屉”的 E2E 测试。

### D-02 【高】【逻辑】删除特性只检查部分引用，仍可删除被穿透/监控/计划引用的特性

- **位置**：`server.js:2384-2395`
- **现象**：删除前只统计 `fmea_row.char_id`、`cp_row.char_id`、`char_link`；未检查 `cp_row.project_char_id`、`fmea_row.process_char_id`、`project_char`、`monitoring_item`、`msa_plan`。
- **触发/影响**：当前 UI 大量使用 `project_char_id`，一条被 CP/SPC/MSA 引用的特性可以被删除，留下孤儿引用；详情页显示空白，SPC 规格丢失。
- **建议**：统一用“引用清单”接口（类似 `server.js:1970-2010`）做删除前检查；所有引用表纳入；或改为“作废”而非物理删除。

### D-03 【中】【逻辑】特性规范修改不会自动更新下游规范限

- **位置**：`lib/deliverable-sync.js:1135-1137`（P2-11 只写 `tol_text`）；`server.js:2345-2380`（特性 PATCH）
- **现象**：修改特性的 `lsl/usl/target` 后，P2-11 交付物只同步 `tol_text`，CP/SPC 读取的规范限仍是旧值或为空。
- **触发/影响**：特性表是“源头”，但规范限没有真正穿透到 CP/SPC/MSA；Cpk 按空规范计算为 `null`。
- **建议**：同步完整规范字段（`lsl/usl/target/unit/tol_text`），并把修改标记为“影响下游”，触发 CP 降级与 SPC 待复核。

### D-04 【中】【操作】快速建特性是两步非原子操作

- **位置**：`public/app.js:8382-8414`
- **现象**：先创建 `char_master`，再创建 `project_char`（或反向），第二步失败时留下半成品。
- **建议**：合并为一个服务端接口并在事务中完成；失败整体回滚。

### D-05 【中】【逻辑】特殊特性标记被压成布尔值，丢失多符号语义

- **位置**：`public/app.js:6172-6217`（`is_special: !!symbol`）
- **现象**：`symbol` 可能是 CC/SC/安全等多种标记，保存时只保留“是否特殊”，具体符号丢失。
- **触发/影响**：CP/FMEA 的特殊特性符号显示与客户要求不一致。
- **建议**：保存 `special_symbol` 原文并保留多值；`is_special` 仅作为派生字段。

### D-06 【中】【逻辑】特性穿透（char_link）缺少重复与环路校验

- **位置**：`server.js:2440-2500` 附近（新增/删除链接）
- **现象**：产品特性↔过程特性是多对多，但没有唯一约束与“同一对已存在”的提示；也没有防止自链接/环路。
- **建议**：`(product_char_id, process_char_id)` 唯一约束；禁止自链接；提供“未关联过程特性的产品特性”清单。

### D-07 【中】【页面】穿透覆盖矩阵用全局数据，且“完整”判定过于宽松

> **修复（v1.6）**：覆盖率已按项目过滤并分五级（已关联→已进 CP→CP 已批准→已监控→MSA 接受）；驾驶舱覆盖率表每行可点击，抽屉展示关联过程特性、CP 行及批准状态、SPC 监控项、MSA 计划与判定，直接定位缺口。

- **位置**：`lib/logic.js:367-373`；`public/app.js:756-769`
- **现象**：覆盖率子查询无项目过滤；前端按 `links/cps/mons` 是否存在判“完整/缺 CP/未纳入 SPC”，不检查 CP 是否批准、监控是否启用、MSA 是否完成。
- **建议**：按项目过滤；覆盖状态改为多级（已关联→已进 CP→CP 已批准→已监控→MSA 已接受）；点击可下钻到具体缺口。

### D-08 【中】【逻辑】质量工具导出使用屏幕当前选择，而非已批准版本

- **位置**：`public/app.js:1525-1528`（`exportQualityTool` 发送 `state.spcId`）；`server.js` 对应导出接口
- **现象**：导出对象是“当前屏幕选中的监控项/CP”，不校验其审批状态；结合 Q-10，可能导出与屏幕不一致的项。
- **建议**：导出前由服务端校验对象状态并返回“导出的是哪一版”；导出记录写入对象 ID、版本与基线。

### D-09 【低】【逻辑】工序字典的生效日期区间没有冲突校验

- **位置**：`server.js:2536-2560`（`POST /api/process-dict`）
- **现象**：同一工序可有多条生效记录，未校验日期区间重叠；停用/新增只按 `status` 判断。
- **建议**：同一 `code` 的生效区间不得重叠；选择工序时按“当前日期 + 状态”过滤。

### D-10 【低】【页面】特性来源列表的展示/解析依赖自由文本

> **修复（v1.6）**：`GET /api/character-sources` 下发 `source_types` 受控词表，前端 datalist 与服务端一致；`POST/PATCH /api/chars` 对来源编号做长度、控制字符、有效字符校验，并把“图纸/国标/GB”等别名归一；词表外的历史自定义类型仍可保存，但响应返回 `source_warning` 提示收敛。

- **位置**：`public/app.js:8109-8136`（`sourceList`）
- **现象**：来源类型/来源编号是自由文本，列表按文本分组；同一来源写法不同会被拆成两组。
- **建议**：来源改为受控字典（客户图纸/标准/试验报告），来源编号做格式校验。
