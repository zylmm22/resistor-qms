# MSA 模块交互关系说明 v1.0（2026-11-05）

- **对象**：`resistor-qms` v1.3.0 MSA 测量系统分析页
- **范围**：四个区域 —— 「APQP MSA 计划」「检具与有效性」「研究设计」「测量数据矩阵 / 研究结果」
- **结论**：计划是唯一的“研究来源”，研究设计是计划的只读投影（临时研究除外），数据矩阵只受研究设计约束，研究结果写回计划状态。本轮修复 14 处交互问题，未改动计算与计划生成规则。

> **2026-11-05 更新：按组织架构拆成两个页签。**
> 页面顶部改为「台账与校准」（企业管理部 · `msa.gauge.edit`）与「研究设计与数据」（质量管理部 · `msa.edit`）。
> 台账页：检具台账与校准、计划待建台账、逐台检具的测量能力评定；研究页：MSA 计划、研究设计、数据矩阵、结果、历史。
> 只有台账权限的账号（如 `metrology01`）默认落在台账页；没有研究权限的账号在研究页只读（按钮禁用、单元格只读，服务端同样 403）。

## 1. 四区域的数据来源

| 区域 | 数据来源 | 过滤规则 |
|---|---|---|
| APQP MSA 计划 | `GET /api/msa` 的 `plans`（`DB.listMsaPlans`） | 只显示当前计划：`source_active≠0` 且状态为 `计划/研究中/待复核`；已完成与来源失效只计数 |
| 检具与有效性 | `GET /api/msa` 的 `gauges` | 台账检具（不含 `planned_only`）+ 计划中待建台账（合成记录，单独分组） |
| 研究设计 · 计划下拉 | `researchPlans` | `msaPlanView === 'planned'` 且 CP 已批准/已冻结（P3-08 计划不限）且同时有项目特性与检具，且为 GRR |
| 研究设计 · 特性/检具/参数 | 选中计划（`data-*`）+ 项目特性 + 检具台账 | 选中计划后整组锁定；临时研究可自由选择 |
| 测量数据矩阵 | 仅由「零件数 × 评价人数 × 试验次数」决定 | 与研究身份（特性/检具/计划）无关，因此换身份必须清空 |
| 研究结果 | `POST /api/msa` 的返回 | 保存后写入 `msa_study`，同时推进计划状态 |

## 2. 依赖关系

```
P3-08 交付物 / 已批准 CP 测量行
        │  ensureMsaPlans（按 source_key 生成/更新）
        ▼
   msa_plan_item ──source_status/source_active──► 计划“待复核 / 已替代 / 来源已失效”
        │ plan_id
        ├──► 「检具与有效性」：按 gauge_id + project_char_id（+ plan_id）找最近研究
        ▼
   「研究设计」：#mPlan 选中 → 锁定 #mChar/#mGauge/#mParts/#mOps/#mTrials/#mTol
        │
        ▼
   「测量数据矩阵」：按维度渲染；生成模拟数据可回填零件真实值
        │ POST /api/msa（plan_id + data + tolerance）
        ▼
   msa_study（已计算）→ 计划置“研究中”
        │ 判定“接受” → POST /msa/:id/complete → 计划“已完成”
        │ 作废 → PATCH /msa/:id/void → 研究“作废”，计划回“计划”
        │ 退回 → PATCH /msa/plans/:id（status=计划，需原因）
        ▼
   PPAP 第 8 项 / 覆盖率 / 仪表盘 / PPAP 质量门
```

## 3. 计划状态机

| 当前 | 动作 | 结果 | 约束 |
|---|---|---|---|
| 计划 | 保存研究 | 研究中 | `requireMsaPlan`：来源有效、CP 已批准/已冻结；研究设计必须与计划一致 |
| 计划 | 手工切换 | 研究中 | `PATCH /msa/plans/:id` |
| 研究中 | 确认完成 | 已完成 | 只有判定“接受”可完成；需填写确认人；研究必须仍是计划当前研究 |
| 研究中 | 退回计划 | 计划 | 必须填写 ≥4 字原因；清空 `study_id` |
| 研究中 | 作废研究 | 计划 | 质量角色 + 原因；研究保留并标作废 |
| 已完成 | 任何回退 | 拒绝 | 需新建复评计划（来源变更会产生新计划） |

## 4. 触发条件表

| 操作 | 会改变什么 | 不会改变什么 |
|---|---|---|
| 选计划 `#mPlan` | 特性、检具、零件数、评价人数、试验次数、容差；锁整组字段；清空数据矩阵与结果 | 历史研究、导出选择 |
| 选“临时研究” | 解锁字段；重置为默认特性 + 首个可用检具 + 10×3×3 | 不写回任何计划 |
| 改特性 `#mChar` | 容差随 LSL/USL 更新；左侧检具状态文字刷新；清空数据矩阵与结果 | 计划表 |
| 改检具 `#mGauge` | 左侧状态、数据矩阵与结果清空（新增） | 计划表 |
| 点检具卡片 | 有匹配计划 → 切到该计划；否则切临时研究并设置检具（均有提示） | 不清空未确认的数据 |
| 改维度 | 重建矩阵；清空结果与模拟缓存 | 特性/检具 |
| 生成模拟数据 | 覆盖矩阵；记录零件真实值 | 不自动保存研究 |
| 计算 GR&R | 写入研究；计划转“研究中”；刷新整页数据 | 判定为“接受”时才出现“确认完成” |

## 5. 本轮修复的问题

| # | 问题 | 修复 |
|---|---|---|
| 1 | 点检具卡片会静默替换计划/特性并清空已录数据 | 统一走 `switchContext()`，有数据先二次确认 |
| 2 | 检具对应计划处于“研究中”时，`#mPlan.value` 被赋不存在的选项 → 点击无反应 | 只从可开展的计划里匹配；否则明确提示“该计划正在研究中，请先退回或以临时研究继续” |
| 3 | `#mGauge` 没有 change 处理器，换设备后矩阵/结果/左侧状态都不变 | 新增处理器，复用 `switchContext()` |
| 4 | 改特性不清矩阵，旧数据可被算到新特性上 | `switchContext()` 统一清空矩阵、模拟提示、结果面板与模拟缓存 |
| 5 | 切计划/改维度后「研究结果」残留，旧“确认完成”按钮仍可点 | 同上 |
| 6 | 「生成模拟数据」覆盖已有数据无确认 | 与维度变化一致，先确认 |
| 7 | 计算后不刷新：计划表仍显示“计划”，历史与导出下拉缺新研究 | 保存后暂存结果 → 重新拉取渲染 → 回填结果面板 |
| 8 | 计划容差为空时 `#mTol` 被禁用，无法按提示补填 | 仅当计划已有公差时禁用 |
| 9 | 模拟与保存可能用不同容差（计划值 vs 表单值） | 统一以表单当前值为准；计划有值时表单即该值并只读 |
| 10 | 左侧检具状态按固定默认值计算，且精确匹配 `plan_id`，真实历史被隐藏 | 跟随当前特性/计划；无计划时按“量具 + 特性”找最近研究，并标注作废/外部研究 |
| 11 | “台可用”把停用/校准过期算作可用；徽标把停用叫“校准过期” | 可用数排除报废+停用；徽标区分“校准过期 / 停用 / 报废” |
| 12 | 导出研究下拉包含作废/来源失效研究 | 过滤并标注状态 |
| 13 | 选“临时研究”不重置，沿用上一个计划的参数 | 回到默认特性 + 首个可用检具 + 10×3×3 |
| 14 | `applyPlan` 给 `#mChar/#mGauge` 赋不到的值 → 控件空白且被禁用 | 赋值后校验，失败回退临时研究并提示原因 |

## 6. 仅记录、未修复

| 事项 | 说明 |
|---|---|
| 同一物理检具可能同时出现在台账与“待建台账” | 服务端只在 `gauge_code` 为空时按名称去重，代码不同的 P3-08 行会产生合成记录；需要调整去重规则 |
| 同一“研究中”计划可被第二次研究覆盖 `study_id` | `requireMsaPlan` 只拒绝“已完成”；第二次保存会让第一次研究成为孤儿。属服务端语义，需要产品确认是否允许 |
| 「研究结果」与「模拟提示」信息架构 | 两者内容有重叠，后续可合并为单一结果区 |
