# 电阻器质量系统 V1.6 实施与验证报告

> 版本：V1.6  
> 实施日期：2026-10-31  
> 范围：新版 PFMEA 功能分析、功能与失效链联合生成、15 条功能上限

---

## 1. 教材依据

本次对照《新版PFMEA教材.pptx》以下章节实施：

- 第 25–31 张：功能分析目的、功能定义、过程项/过程步骤/过程工作要素功能。
- 第 32–35 张：产品特性、过程特性、功能关系可视化和失效分析基础。
- 第 37–46 张：失效链、失效影响、失效模式和失效起因。
- 第 47–51 张：遗漏、过多、过少、不完整、不一致、过快、过慢等失效模式。
- 第 52–55 张：人员、设备、材料、环境等 4M 失效起因。

教材核心口径：

```text
功能 = 现在时动作动词 + 对象 + 可判断或测量的要求
失效影响 FE = 过程项功能的反面
失效模式 FM = 过程步骤功能的反面
失效起因 FC = 过程工作要素功能的反面
```

功能描述不能直接复制操作方法长句；失效模式不能使用“尺寸偏差、功能失效、不良、异常”等空泛词。

## 2. 功能生成页面

### 2.1 大白话输入

主输入框只用于填写口语描述，例如：

```text
激光划线机要按产品尺寸在陶瓷基片上划出预切线，让后面掰条、分粒时沿着划线整齐断开，
不能划伤基片，也不能划得太浅或太深，划线位置和槽深要稳定。
```

AI 会结合当前结构节点、工序号、设备、输入、输出和项目特性，把它拆成标准功能，而不是原样写入。

### 2.2 功能与失效链联合生成

每次生成 3 条新功能候选，每条候选同时生成 2–4 条对应失效链：

- FE：下道工序、工厂或最终用户影响。
- FM：当前功能未实现或异常实现的具体技术形态。
- FC：人员、设备、材料、环境或方法的具体原因。
- PC：防止起因发生的具体现行控制。
- DC：检出模式或起因的方法和频次。
- S：严重度。

功能候选和失效候选一次写入数据库。采用功能后直接显示已生成的失效候选，不再重新猜测功能。

### 2.3 手工入口

“口语化描述”和“手工补充标准功能”已拆成两个输入框，避免把大白话直接当标准功能写入。

服务器会校验手工功能：

- 使用动作动词。
- 不包含失效、故障等反向词。
- 不接受纯口语化长句。

## 3. 候选数量与去重

- 每个结构节点最多保存 15 条功能，包括已采用和未采用候选。
- 每次点击生成 3 条；剩余容量不足 3 条时，只生成剩余数量。
- 达到 15 条后，生成按钮禁用并显示上限提示。
- 新生成的功能必须与已采用功能和全部已有候选不同。
- 删除功能时同步删除它对应的失效候选。
- 再次点击失效分析中的“再生成 3 条”，只追加新的失效模式，不返回旧缓存，也不重复已有模式。

## 4. AI 错误与本地兜底

当前保存的 AI Key 经实际调用返回 HTTP 401，服务商提示 Key 无效或无权限。

系统现在会明确提示：

```text
AI Key 无效或无权限，请在 AI 设置中更新有效 Key
```

AI 不可用时，本地规则仍会结合当前工序生成候选，不再使用原来的固定“尺寸偏差/功能失效”：

- 从工序输出中提取量化要求，例如“槽深 21±3 μm”。
- 从输入、设备和项目特性中提取对象及控制参数。
- 功能和失效模式包含具体工序、对象、特性或控制。
- PC、DC 不再留空或写“待补充”。

## 5. 验证结果

### 5.1 自动化测试

执行：

```text
npm test
```

结果：`Smoke tests passed`

覆盖内容：

- 功能候选同时包含失效链。
- 连续生成排除已采用及已存在功能。
- 两次连续生成产生 6 条不同功能。
- 功能采用后已存在失效候选。
- 再次生成追加 3 条不同失效模式。
- 达到 15 条功能后阻止继续生成。
- 失效候选的 PC/DC 完整。

### 5.2 浏览器验证

- 旧“重新生成候选”按钮已移除。
- 口语化描述框和手工标准功能框分离。
- 实际生成后，候选从 9 条增加到 12 条。
- 采用新功能后显示 2 条对应失效候选。
- 页面没有“待补充”文本。
- PC、DC 均已生成。
- 浏览器未捕获 JavaScript 页面错误。

### 5.3 AI 实际连通性

已使用数据库副本真实请求 DeepSeek：

```text
HTTP 401
Authentication Fails
API Key invalid
```

因此外部 AI 标准输出路径已完成实现，但需要在“AI 设置”中更新有效 Key 后才能进行真实模型效果验收。
