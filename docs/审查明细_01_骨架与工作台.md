## 本模块结论

骨架层的问题不是零散 UI 瑕疵，而是三类“同一事实、多套口径”：

1. **Gate 结论三套口径**——接口按 `criteria_version` 判“待复核”，预警与驾驶舱仍按旧记录算“通过”。
2. **项目上下文不闭环**——多条查询没有 `project_id`，`?p=` 也没有成员校验，A 项目能看到 B 项目的数据。
3. **身份不可信**——操作人/审批人大量来自请求体或硬编码，角色只拦 `auditor`，`engineer` 与 `quality` 权限完全相同。

这三类会污染所有上层模块的结论，建议优先修。

### S-01 【高】【逻辑】Gate 结论在三个页面各算一套

- **位置**：`server.js:6903-6988`；`lib/logic.js:448-460`；`lib/logic.js:541-545`
- **现象**：
  - `/api/gates` 按当前 `criteria_version` 判定：旧版本记录返回 `decision='待复核'`、`checks` 全 0，且 `canReview` 要求前一 Gate 以当前版本通过。
  - `L.alerts` 的 Gate 预警直接读 `gate_review.decision`，完全不比对版本。
  - `L.cockpit` 的 `passed = gates.filter(g => g.decision === '通过').length`，同样不看版本。
- **触发/影响**：升级检查表版本后，Gate 页显示“待复核”，总览不预警、驾驶舱仍把旧版通过计入健康分。同一项目在三个页面对“Gate 是否通过”给出相反答案，评审结论无法作为放行依据。
- **建议**：抽一个 `gateStatus(projectId, criteriaVersion)` 服务端函数，Gate 页、预警、驾驶舱、PPAP 就绪统一调用；旧版本记录统一映射为“待复核”并在 UI 标注“检查表已升级”。

### S-02 【高】【逻辑】多条聚合查询没有项目隔离

- **位置**：`lib/logic.js:367-373`（`charCoverage` 的 `cps`/`mons` 子查询无 `project_id`）；`lib/logic.js:396`（`audit` 全库）；`lib/logic.js:321-398` 的 `counts.chars/links`；`lib/db.js:911+`（`freezeBaseline` 的 GAUGE/CHAR 快照）
- **现象**：仪表盘“特性覆盖率”里的 CP 行数与 SPC 监控数取全库；审计列表取全库最近 8 条；基线冻结的检具/特性快照也不按项目过滤。
- **触发/影响**：同一实例有 2 个以上项目时，总览的覆盖表、首页审计流、基线内容都会混入其他项目数据。前端 `app.js:749-769` 直接渲染这些字段，用户无法分辨。
- **建议**：给每条查询补 `project_id=?`（`char_link` 通过 `project_char.project_id` 关联）；基线快照只取本项目检具/特性；补一条“两项目并存”的集成测试。

### S-03 【高】【安全/逻辑】操作人与审批人可伪造或硬编码

- **位置**：
  - `server.js:6963` Gate：`reviewer = body.reviewer || requestContext...user.display_name`
  - `server.js:244-254` `recordApproval`：`requestedBy = '张工艺'` 默认值
  - `server.js:2925/2938/2977/2999/3303/3350/3474` FMEA 审计固定 `'张工艺'`/`'设计-陈'`
  - `server.js:3508` FMEA 决定审计固定 `'质量经理 王'`
  - `server.js:4175` SPC 导入固定 `'质检-陈'`
  - `server.js:5195` PPAP 状态变更固定 `'质量经理 王'`
  - `server.js:2679` PFD 发布 `published_by = body.user || '工艺-张'`
  - 前端默认值：`app.js:921/948/956`、`2342/2356/2393`、`7340`
- **触发/影响**：任何调用方在请求体里写任意名字即可成为“批准人”；更多路径干脆写死姓名。审计表 `audit_event`、`activity_approval`、`project_doc_revision` 因此不能证明“谁批准的”，受控文件与 PPAP 的证据链失效。
- **建议**：服务端统一 `actor = requestContext.user.display_name`，并禁止请求体覆盖；历史数据做一次归属映射；前端把审批人改为只读展示，不再提供输入框。

### S-04 【高】【安全】默认口令与 RBAC 形同虚设

- **位置**：`lib/db.js:1676-1679`（`admin123`/`engineer123`/`quality123`/`auditor123`，仅当环境变量未设置时生效）；`server.js:7863-7870`（仅拦 `auditor` 的非 GET 与 `/api/admin/`）；`public/app.js:7495`（提示语自认“当前系统尚未启用登录级越权拦截”）
- **现象**：`engineer` 与 `quality` 的实际权限完全相同；任何非 `auditor` 用户都能批准、冻结基线、提交 PPAP、批准 FMEA 决定；未设置环境变量时四个默认口令可直接登录。
- **触发/影响**：这是“受控系统”最根本的合规缺口：工艺工程师可自批自己编制的控制计划与 PPAP。审核员只能只读，反而说明角色模型只实现了“只读/非只读”两档。
- **建议**：建立动作级权限表（编制/审核/批准/冻结/发布/删除分别授权）；批准类接口校验角色且禁止“编制人=批准人”；启动时若使用默认口令则强制改密或拒绝启动；在 README 与登录页明确演示账号仅用于本地演示。

### S-05 【高】【逻辑】`?p=` 项目切换无成员校验，且依赖 `AsyncLocalStorage.enterWith`

- **位置**：`server.js:7830-7832`；`globalThis.CUR` getter
- **现象**：`requestProject = wantP || DEFAULT_PROJECT`，只要传 `?p=` 就能读写任意项目，不校验当前用户是否属于该项目；`requestContext.enterWith(...)` 把上下文写入当前异步链，若某条路径复用了其他请求的异步资源（或后台定时器/启动同步），`CUR` 可能串到别的项目。
- **触发/影响**：越权访问；以及在并发/后台任务下出现“写错项目”的隐蔽数据污染。
- **建议**：`?p=` 必须命中 `auth_user_project` 之类的关系表；`CUR` 改为显式传参（或在每个 handler 开头解构一次），后台任务显式带 `projectId`，不要依赖隐式上下文。

### S-06 【中】【逻辑】项目阶段只增不减，且与 Gate 结论脱钩

- **位置**：`server.js:6963-6985` 附近（Gate 通过后 `project.phase = Math.min(5, phase + 1)`）
- **现象**：Gate 通过即把阶段 +1；Gate 被驳回、检查表升级、交付物退回都不会让阶段回退；阶段也不会根据实际 Gate 状态重算。
- **触发/影响**：项目可以停留在“阶段 4”而阶段 2 的 Gate 已被驳回；阶段 0 在 UI 上显示为“—”（见 S-07）。
- **建议**：阶段改为由 Gate 结论派生（只读投影），或提供受控的回退动作并写审计；不要在 Gate 接口里直接改 `project.phase`。

### S-07 【中】【页面】阶段名称错位（1-based 表 vs 0-based 值）

- **位置**：`public/app.js:157`（`phaseName = n => ['', '策划与准备', '产品设计', '过程设计', '产品与过程确认', '量产与持续改进'][n] || '—'`）；`public/app.js:713` 使用 `state.meta.project.phase`
- **现象**：`project.phase` 是 0–5，`phaseName` 的下标却从 1 开始（数组第 0 项为空串）。
- **触发/影响**：phase=0 显示“—”，phase=3 显示“产品与过程确认”（实际应为“过程设计”），所有阶段标签整体前移一位。
- **建议**：统一 0-based 数组，或调用处 `phaseName(phase + 1)`；补一个覆盖 0–5 的渲染快照测试。

### S-08 【中】【操作】Gate 一键通过无二次确认、无评审意见、不可撤回

- **位置**：`public/app.js:799-867`；`server.js:6903-6988`
- **现象**：勾选全部检查项后点击按钮即提交“通过”，没有确认对话框；“通过”不要求填写评审意见或附件；通过后没有撤回/重开接口（只能等检查表升版把它变成“待复核”）。
- **触发/影响**：误点即可推进项目阶段；评审过程没有留下“为什么通过”的记录。
- **建议**：通过前二次确认并强制填写结论意见；支持“撤回评审”（需更高角色并写审计）；通过按钮与驳回按钮做视觉区分。

### S-09 【中】【操作】切换项目只清 5 个状态，残留其他项目的选择与缓存

- **位置**：`public/app.js:361-389`
- **现象**：`switchProject` 只重置少数字段，随后直接重绘当前视图；文档缓存、筛选条件、选中的 FMEA 行/CP 行/监控项等仍保留上一项目的值。
- **触发/影响**：切换项目后详情抽屉可能显示上一项目的记录；某些“当前选中 ID”会让新项目页面直接报“记录不存在”。
- **建议**：项目切换视为“会话级重置”，统一重建 `state` 并回到总览；不要复用上一项目的任何选中态。

### S-10 【中】【页面】顶部角色下拉与实际权限不一致

- **位置**：`public/app.js:361-374`、`7495`
- **现象**：下拉被 `disabled`，但 `admin` 映射成“系统管理员”，该文案不在选项列表中；切换角色只弹提示，不改变后端权限；提示语直接写着“尚未启用登录级越权拦截”。
- **触发/影响**：用户以为切换角色会切换权限，实际只是改变显示；演示时容易误判系统能力。
- **建议**：角色只读展示当前登录用户；如需演示切换，明确标注“仅切换视图，不改变权限”，并移除自认缺陷的提示语。

### S-11 【中】【操作】前端路由只用 `replaceState`，浏览器后退失效

- **位置**：`public/app.js:293-358`、`402`
- **现象**：`go(v)` 与深链更新都用 `history.replaceState`，从不 `pushState`，也没有 `popstate` 监听；部分历史哈希（如 `#row-new-ai`）已无对应处理分支。
- **触发/影响**：在模块间跳转后按浏览器后退会直接退出应用或回到最初页面；刷新可恢复，但“后退一步”这一基本操作不可用。
- **建议**：导航改 `pushState` + `popstate` 分发；清理失效哈希分支；对未知哈希给“页面不存在”提示而不是静默回落。

### S-12 【中】【页面】总览“可提交 PPAP”在 0 项时判定为真

- **位置**：`public/app.js:689-690`
- **现象**：`d.ppapDone === d.ppapTotal` 在 `0 === 0` 时为真，直接显示“可提交”；`bar((ppapDone / ppapTotal) * 100)` 得到 `NaN`。
- **触发/影响**：新项目首页显示“可提交 PPAP”与一条 NaN 进度条，误导用户直接去提交。
- **建议**：分母为 0 时显示“未开始”，并复用 PPAP 就绪接口的 `missing` 结果，而不是只比数量。

### S-13 【中】【页面】同一阶段存在三套完成度分母

- **位置**：`public/app.js:664`（`docsDone/docsTotal`）、`715-719`（CATALOG 项数）、`1289`（交付物 `pct`）
- **现象**：总览头部百分比用“已存在 `project_doc` 行数 / 实际行数”，阶段卡用 CATALOG 条目数，交付物列表用字段完成度。
- **触发/影响**：同一阶段在三个位置显示不同百分比；用户无法判断“还差什么”。
- **建议**：定义唯一“交付物完成度”投影（CATALOG 为分母、必填字段为权重），三处共用；把“未建行”和“建行但空”分开统计。

### S-14 【中】【页面】首页审计流展示全库事件

- **位置**：`public/app.js:749-750`；`lib/logic.js:396`
- **现象**：`audit: all('SELECT * FROM audit_event ORDER BY event_id DESC LIMIT 8')` 没有项目过滤，前端原样渲染。
- **触发/影响**：其他项目的操作（甚至系统初始化）出现在本项目首页；审计信息泄露项目边界。
- **建议**：按 `project_id` 过滤；全局事件放到“系统日志”页并加权限。

### S-15 【中】【逻辑】启动时全量写同步，副作用不可控

- **位置**：`server.js:130-158`；启动流程
- **现象**：启动即调用 `syncProjectDeliverables`（DS + CS + `ensureMsaPlans` 汇总冲突），会写 `project_doc`/`control_plan`/`msa_plan` 并产生审计/冲突记录。
- **触发/影响**：项目多时启动变慢；每次重启都会“修正”数据，掩盖真实的状态漂移；某个项目数据异常会让启动同步整体失败（当前是否吞异常需确认）。
- **建议**：启动只做只读校验并输出报告；同步改为显式“重算”按钮或迁移脚本；失败逐项目隔离并写日志。

### S-16 【中】【逻辑】`DB.tx()` 对 async 回调会提前提交

- **位置**：`lib/db.js` `tx()`（SAVEPOINT/RELEASE/ROLLBACK）
- **现象**：事务包装是同步的；若回调 `async` 并 `await`，`tx()` 在第一个 await 处就执行 `RELEASE`，后续写操作落在事务之外，回滚也不再覆盖它们。
- **触发/影响**：目前多数 handler 是同步的，但一旦有人在事务里 await（如导出、文件写入、外部调用），就会出现“部分提交”的脏数据，且难以复现。
- **建议**：`tx()` 检测返回值是否为 Promise，是则抛错；或提供 `txAsync()` 明确支持异步；在代码规范里禁止在 `tx` 内 await。

### S-17 【低】【页面】移动端宽表被整体裁切

- **位置**：`public/style.css:22`（`body{overflow-x:hidden}`）、`602`（仅 `.qt-table-wrap` 有 sticky）
- **现象**：多数业务宽表没有独立横向滚动容器，`body` 禁止横向滚动后列被裁掉。
- **触发/影响**：手机/小屏无法看到右侧列（如 AP、Cpk、判定）。
- **建议**：所有宽表包一层 `overflow-x:auto` 容器；表头 sticky；给关键列设置最小宽度而非整体缩放。

### S-18 【低】【页面】缺少键盘焦点样式与动效降级

- **位置**：`public/style.css`（无 `:focus-visible`、无 `prefers-reduced-motion`）
- **现象**：键盘 Tab 时焦点不可见；过渡/动画不响应系统“减少动态效果”设置。
- **建议**：补 `:focus-visible` 轮廓；用 `@media (prefers-reduced-motion: reduce)` 关闭非必要动画。

### S-19 【低】【逻辑】前端存在两份 `api()` 实现

- **位置**：`public/app.js:10`、`public/app.js:216`
- **现象**：两处同名函数，错误处理/401 跳转/JSON 解析行为可能不同；后定义的覆盖前定义，阅读与维护容易踩坑。
- **建议**：合并为一个模块级函数，统一 401 处理与错误 toast。

### S-20 【低】【页面】README 中的交付物计数与代码不一致
