# 电阻器质量系统：项目功能全量清单与操作逻辑

> 版本：V1.0  
> 整理日期：2026-10-30  
> 分析对象：`resistor-qms` 运行系统、`电阻器FMEA系统_交付` 中的需求规格、技术评审、数据字典及四套模板  
> 用途：作为一次性的业务确认与优化需求输入基线。后续可直接按本文的功能 ID 提出“保留 / 修改 / 删除 / 新增 / 优先级 / 验收标准”。

配套可填写文件：`项目功能清单与改进需求征集表_v1.0.xlsx`

## 0. 先看结论

### 0.1 当前项目到底是什么

这是一个**可运行的本地单机质量管理系统原型**，不是已经具备生产级权限、审计和受控文件能力的正式 QMS。

已形成较完整数据链路的模块：

1. 项目清单与项目切换。
2. APQP 阶段、交付物目录、在线表单、Word/Excel 导出。
3. DFMEA/PFMEA 七步法工作表、功能、失效行、决定、措施、AI 候选。
4. PFD 工序表、流程示意、从图片识别工序。
5. 控制计划人工维护与 PFMEA + PFD 自动映射。
6. SPC 的 Xbar-R 控制图、Cp/Cpk、Pp/Ppk。
7. MSA 均值-极差法 GR&R。
8. PPAP 18 项清单与打包哈希记录。
9. 基线快照与两基线字段级差异。
10. Gate 评审、预警中心、管理驾驶舱。

### 0.2 必须区分的四种状态

| 状态 | 含义 |
|---|---|
| `已实现` | 界面、接口和数据库写入链路都存在，主要操作可运行。 |
| `部分实现` | 页面或数据结构存在，但缺少关键闭环、联动、校验或完整维护入口。 |
| `仅展示/派生` | 只显示计算或汇总结果，不能在页面完成对应业务操作。 |
| `规划/未实现` | 文档或菜单中提到，但当前代码没有可用的业务实现。 |

### 0.3 文档与代码的真实数量差异

| 项目 | 交付文档说法 | 当前代码实际 |
|---|---:|---:|
| APQP 交付物 | README 写“38 份”，SRS 写“75 项” | `CATALOG` 实际 **67 项** |
| 在线专用表单 | README 写“29 份模板” | 44 个 form 中，33 个有专用结构，11 个检查表回退到通用表单 |
| 数据库表 | README/数据字典写“24 张业务表” | 源码定义 **34 张表**，运行库还含若干源码未声明的增量字段 |
| 需求条目 | SRS 写 74 条 FR + 12 条 NFR | 当前代码只覆盖其中一部分，且额外实现了 Gate、AI/OCR、SPC/MSA/PPAP 等 |

APQP 67 项的分布如下：

| 阶段 | 全部 | 输入 | 输出 | 活动 | 检查表 | 表单 | 系统模块 | 纯活动/占位 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| P0 入门 | 4 | 0 | 1 | 2 | 1 | 2 | 0 | 2 |
| P1 策划和定义 | 17 | 6 | 11 | 0 | 0 | 10 | 0 | 7 |
| P2 产品设计 | 16 | 0 | 13 | 0 | 3 | 15 | 1 | 0 |
| P3 过程设计 | 16 | 0 | 10 | 0 | 6 | 12 | 3 | 1 |
| P4 产品过程确认 | 10 | 0 | 8 | 1 | 1 | 5 | 4 | 1 |
| P5 反馈改进 | 4 | 0 | 0 | 4 | 0 | 0 | 0 | 4 |
| **合计** | **67** | **6** | **43** | **7** | **11** | **44** | **8** | **15** |

另外，`lib/doctpl.js` 中还有一个未进入目录的 `P0-11` 模板结构；不会出现在 APQP 清单里，属于孤立模板配置。

### 0.4 对“一次性提优化”的建议

后续反馈建议统一写成下面的格式：

```text
功能ID | 处理方式（保留/修改/删除/新增） | 优先级（P0/P1/P2） |
现状问题 | 期望行为 | 验收口径 | 是否影响历史数据
```

文末提供了逐项填写模板，也可以直接在每个模块表的“改进建议”列中填写。

## 1. 系统架构与数据主线

### 1.1 技术结构

| 层 | 当前实现 |
|---|---|
| 运行时 | Node.js，使用内置 `node:sqlite` |
| 服务端 | 原生 `http`，手写正则路由，85 个显式 API 路由 |
| 数据库 | SQLite，WAL 模式，默认文件 `data/qms.db` |
| 前端 | 原生 JavaScript 单页应用，哈希路由，无构建步骤 |
| 文件导出 | 自写 ZIP/OOXML，生成 `.docx` 和 `.xlsx` |
| OCR | Windows.Media.Ocr 本机离线识别，仅 Windows |
| AI | OpenAI Chat Completions 协议，可接 DeepSeek、通义、Ollama、vLLM |
| 认证 | 无 |
| 权限 | 角色下拉仅展示，无后端鉴权 |
| 并发 | 默认单用户本地运行；所有请求共享一个全局 `CUR` 当前项目变量 |

### 1.2 核心业务主线

```text
顾客要求 / 设计目标 / 特殊特性
        ↓
      DFMEA
        ↓
产品特性 ←→ CharLink（M:N）←→ 过程特性
        ↓
       PFD
        ↓
      PFMEA
        ↓
控制计划 CP
        ↓
监控项 MonitoringItem
        ↓
      SPC / MSA
        ↓
       PPAP
        ↓
基线快照 / 版本差异 / 变更
```

### 1.3 项目隔离与共享边界

| 数据 | 隔离方式 | 当前实际效果 |
|---|---|---|
| 项目 | 按 `project_id` 隔离 | 页面切换时通过 `?p=项目ID` 传参 |
| APQP 交付物 | 按项目写入 `project_doc` | 项目间内容隔离 |
| PFD 工序 | 按项目 | 项目间隔离 |
| FMEA 表头、节点、分析行 | 按项目的 FMEA Header 隔离 | 项目间隔离 |
| 控制计划 | 按项目 | 当前每个项目只有一个 CP 头 |
| SPC、MSA、PPAP、基线 | 按项目 | 大部分按项目查询 |
| 特性主数据 `char_master` | 全局共享 | 没有按产品族过滤 |
| 特性关联 `char_link` | 全局共享 | 没有项目或产品族字段 |
| 检具台账 `gauge` | 全局共享 | 所有项目看到同一套检具 |
| AP 矩阵 `ap_matrix` | 全局共享 | 实际判定还硬编码在源码中 |
| 自定义模板 `doc_template` | 全局共享 | 所有项目都能看到、编辑、删除 |
| 审计事件 | 全局共享 | 没有项目字段，列表展示全部事件 |

### 1.4 真实数据库表分组

| 域 | 表 |
|---|---|
| 主数据 | `product_family`、`project`、`char_master`、`char_link` |
| FMEA | `fmea_header`、`fmea_node`、`fmea_row`、`fmea_action`、`fmea_decision`、`fmea_function`、`fmea_failure_cand`、`fmea_image` |
| 工艺 | `process_step` |
| 控制计划 | `control_plan`、`cp_row` |

| APQP | `apqp_phase`、`apqp_task`、`project_doc`、`doc_template`、`ppap_element`、`ppap_package` |
| 治理 | `baseline`、`baseline_item`、`change_request`、`change_item`、`ecr`、`gate_review`、`audit_event` |
| 规则与设置 | `ap_matrix`、`app_setting` |

**阶段完成度口径风险：**

- 仪表盘和驾驶舱把“系统模块”计入总项，但只把 `status = 已完成` 计为完成。
- 系统模块的初始状态是“系统模块”，没有“标记完成”入口。
- 因此阶段完成度和健康度可能永远无法自然达到 100%。
- 项目卡片又排除了系统模块，三个页面的完成度口径不一致。

### 8.1 SPC 公式摘要

设子组大小为 `n`，子组均值为 \(\bar{x}_i\)，子组极差为 \(R_i\)：

```text
X̄̄ = 所有子组均值的平均
R̄  = 所有子组极差的平均
σ组内 = R̄ / d2(n)
UCLx = X̄̄ + A2(n) × R̄
LCLx = X̄̄ - A2(n) × R̄
UCLr = D4(n) × R̄
LCLr = D3(n) × R̄
Cp  = (USL - LSL) / (6 × σ组内)
Cpk = min((USL - X̄̄)/(3σ组内), (X̄̄ - LSL)/(3σ组内))
Ppk = min((USL - X̄̄)/(3σ总体), (X̄̄ - LSL)/(3σ总体))
```

### 9.1 MSA 公式摘要

```text
EV = 同一人同件多次测量的平均极差 / d2(试验次数)
AV = sqrt(max(0, (评价人均值极差 / d2(评价人数))² - EV²/(零件数×试验次数)))
GRR = sqrt(EV² + AV²)
PV = 零件均值极差 / d2(零件数)
TV = sqrt(GRR² + PV²)
%GRR = GRR / TV × 100%
%EV = EV / TV × 100%
%AV = AV / TV × 100%
ndc = floor(1.41 × PV / GRR)
```

## 13. 关键端到端操作逻辑

### 13.1 新建项目

1. 点击“项目清单 → 新建项目”。
2. 填写项目名称、可选项目编号、零件号、客户。
3. 点击“创建”。
4. 服务端创建 `project` 行。
5. 创建 P0–P5 的 6 条 `apqp_phase`。
6. 为 67 个目录项创建 `project_doc` 记录。
7. 创建 DFMEA 和 PFMEA 表头。
8. 创建一个阶段为 `PROTO` 的控制计划头。
9. 返回新项目 ID，项目清单刷新。

当前缺口：

- 不复制已有项目。
- 不创建 APQP 任务。
- 不创建 18 项 PPAP 要素。
- 不创建 Gate 计划记录。
- 不创建 FMEA 根结构。
- 不创建 CP 行。
- 不初始化项目级模板或文件编号序列。

### 13.2 编辑 APQP 交付物

1. 在 APQP 阶段表点击“编辑”。
2. 系统读取内置 schema 和当前项目数据。
3. 修改字段、表格行、表格列名或状态。
4. 1.5 秒后自动保存，或按 `Ctrl+S` 手动保存。
5. 服务端重新计算完成度，并在未指定状态时自动写“草稿/已完成”。
6. 可下载 Word 或 Excel。

注意：

- 完成度按字段数量计算，表格只算一个字段。
- 版本号不递增。
- 历史修订不保留。
- 下载使用系统 schema 重建文件，不保留原模板全部样式。

### 13.3 上传客户模板

1. 点击“上传模板”，选择 `.xlsx` 或 `.docx`。
2. 前端把文件转 Base64 发给服务端。
3. 服务端先尝试 XLSX 解析，失败后尝试 DOCX。
4. XLSX 选内容最多的一个 Sheet，识别合并、列宽、粗体和表头。
5. Word 按段落和表格拆成文本、字段和表格块。
6. 规则引擎生成填写说明。
7. 写入全局 `doc_template`。
8. 页面打开网格或文档编辑器，输入后自动保存。

注意：

- 不绑定客户模板坐标，不把模板单元格映射到 FMEA/CP 业务字段。
- 不保留公式、图片、条件格式、宏、页眉页脚。
- 多 Sheet 只取一个。
- 服务端一般请求体上限是 4 MB，Base64 会放大约 4/3，所以页面的 12 MB 文件限制实际很难达到。

### 13.4 从 PFD 生成 PFMEA 结构

1. 打开 PFMEA。
2. 选择“仅工序层”或“工序 + 4M 要素”。
3. 点击“从 PFD 生成结构”。
4. 系统先删除上次标记为“由工序流程图生成”的根树。
5. 新建“项目名 过程总成”根节点。
6. 每道工序生成一个 level=2 过程步骤。
7. 若选 4M，再为每道工序生成“人/机/法/环”4 个 level=3 节点。
8. 旧的 FMEA 行的 `focus_node_id` 会被置空，但行本身不删除。

风险：

- 旧行会变成“未关联结构”。
- 旧功能、候选、措施、决定没有统一清理策略。
- 不校验 PFD 是否已发布。
- 不记录上游 PFD 版本。

### 13.5 从示意图生成 DFMEA 结构

1. 在 DFMEA 点击“从示意图生成结构”。
2. 上传、粘贴或加载示例图片。
3. 服务端调用 Windows OCR。
4. 词典和规则把文字切成结构标签。
5. 页面展示可编辑标签。
6. 点击“生成结构树预览”，规则将标签归为芯体、膜层、保护层、引出端、结构特征、其他。
7. 点击“写入 DFMEA 结构”。
8. 删除上次由示意图生成的根树，写入新根、组和零件节点，并保存图片与标签。

当前限制：

- 新节点未设置 `level`，FMEA 报告的三级统计会把它漏掉。
- 功能建议写在节点 `desc` 中，不直接创建正式 `fmea_function`；重启后迁移逻辑才可能转成功能。
- 不识别标注引线、箭头和真实装配关系。

### 13.6 新增或编辑 FMEA 分析行

1. 点击结构节点或功能行的“＋失效分析”。
2. 选择/填写 FE、FM、FC。
3. 选择关联产品特性。
4. PFMEA 选择关联工序。
5. 选择本行针对的功能。
6. 填写 PC、DC。
7. 分别填写三个场景的 S，系统取最大；填写 O、D。
8. 前端即时预览 AP。
9. 点击“保存分析行”。
10. 服务端校验 FE/FM/FC/PC/DC、S/O/D 范围、同 FE 的 S 一致性。
11. 服务端按 FE/FM/FC 文本查找或创建失效节点。
12. 写入分析行并审核日志。

当前限制：

- 同一 FE+FM+FC 没有数据库唯一约束。
- 产品特性与过程特性未在分析行分开维护。
- `effect_ref` 同时承担“功能 ID”和“上游 DFMEA 行 ID”两种语义。
- 新行编号按当前行数生成，删除后可撞号。

### 13.7 登记 AP=H 的决定和措施

1. 打开已有分析行。
2. AP=H 时页面默认选择“采取措施”。
3. 可改成“经论证不采取措施”，此时理由必须至少 30 字。
4. S ≥ 9 且不是采取措施时，必须填写批准人。
5. 可填写复审日期，点击“登记决定”。
6. 可新增措施，填写责任、日期、状态、证据和措施后 S/O/D。
7. 三项重评分都存在时自动计算措施后 AP。

当前缺口：

- 分析行保存与决定保存是两个动作，没有“AP=H 未决定不得提交/发布”的状态机。
- 措施状态不能在页面更新。
- 复审日期到期不预警。
- 措施有效性验证没有页面入口和状态限制。

### 13.8 CP 自动映射

1. 点击“控制计划 → 一键自动映射”。
2. 系统读取当前项目全部 PFD 工序。
3. 读取当前项目 PFMEA 行及其关联特性。
4. 按 `(step_id, char_id)` 分组，合并同组 PC/DC 文本。
5. 已有且人工覆盖的 CP 行跳过。
6. 已有且未覆盖的 CP 行更新规范、测量技术、控制方法和 FMEA 行 ID。
7. 不存在的组合新增 CP 行。
8. 对没有任何 PFMEA 特性的工序补一行“基础控制”。

当前限制：

- 不会创建 `monitoring_item`。
- 人工覆盖是行级，不是字段级。
- 新行默认样本 1、频率 2 小时、触发条件巡检。
- 上游版本写死为 `PF-0001 r2`。
- 当前项目只有一张 CP，无法区分试生产和量产。

### 13.9 SPC 导入和计算

1. 选择监控项页签。
2. 页面读取该监控项最新数据集。
3. 粘贴至少 5 行子组数据。
4. 提交。
5. 服务端校验每行数量等于 `subgroup_n`。
6. 保存原始 JSON 和哈希。
7. 页面重新读取最新数据，计算控制图、Cp/Cpk/Pp/Ppk 和判异项。

边界：

- 不支持 Excel 上传。
- 不支持历史数据切换。
- 不支持单边规格能力。
- 没有分选前取样校验。
- 数据输入不是有限数值时可能产生异常计算。

### 13.10 PPAP 冻结和打包

1. 打开 PPAP。
2. 逐项把 18 项标记完成/未完成。
3. 点击“冻结基线并打包”。
4. 系统创建新基线，快照当前特性、工序、FMEA 行和 CP 行。
5. 读取最新基线及 18 项要素。
6. 生成 manifest，计算 SHA-256。
7. 写入 `ppap_package`。

边界：

- 不生成真实 ZIP。
- 不打包实际 Word/Excel/SPC/MSA 文件。
- 不检查 18 项是否齐全。
- 不按提交等级确定必需项。
- 包内没有逐文件哈希。

### 13.11 基线差异

1. 冻结至少两次基线。
2. 在“基线与变更”选择基线 A 和 B。
3. 点击“对比”。
4. 系统按 `object_type + object_id` 对齐。
5. 输出新增、删除、修改三类对象。
6. 修改对象再逐字段比较 `snapshot JSON`。
7. 数值公差字段尝试判断收紧/放宽。

边界：

- 只能在页面查看，不能导出报告。
- 没有对象快照浏览。
- 没覆盖 CharLink、FMEA 措施/决定、文档、SPC、MSA、PPAP。
- 冻结没有显式事务。

### 13.12 Gate 评审

1. 打开“门径评审”。
2. 逐项勾选当前 Gate 的检查项。
3. 填写评审意见。
4. 点击通过、驳回或保存待评审。
5. 通过时后端要求检查项全部为真。
6. 通过后若当前 Gate 不早于项目阶段，项目阶段推进一级。

边界：

- 检查项不自动取证。
- 可以跳过前置 Gate。
- 没有评审人登录校验。

## 14. 当前完成度较高的逻辑

以下逻辑与项目目标较一致，建议优先保留：

1. **AP 查表而不是 RPN 相乘**：前端和后端都按同一区间规则查 AP。
2. **同一失效影响 S 一致**：保存分析行时服务端强制校验。
3. **一行一失效原因的工作表模型**：UI 和查询结构以 FE+FM+FC 行呈现。
4. **AP=H 强制处置决定**：不是强制写措施，而是可登记“采取措施/不采取措施/待评审”。
5. **高严重度审批门槛**：S ≥ 9 的非采取措施决定要求批准人。
6. **CP 特性 ID 引用**：CP 表中特性名称来自特性主数据，而不是完全自由文本。
7. **CP 人工覆盖保护**：自动映射不会覆盖已标记的人工行。
8. **PFD 工序 ID 与工序号分离**：插入或修改工序号不改工序 ID。
9. **Cpk/Ppk 口径分离**：Cpk 用组内 σ，Ppk 用总体 σ。
10. **基线按对象级哈希**：具备对象级和字段级差异基础。
11. **AI 候选不直接入库为正式行**：采用和保存分离。
12. **OCR 全程本地**：图纸内容不发送外部服务。

6. 增加 CharLink 维护入口。
7. 把 FMEA 功能关联和上游引用拆成两个字段。

### 第二阶段：补齐审核证据

1. 登录、角色、对象级权限。
2. 文档提交、审核、批准、退回、批准人和审批历史。
3. FMEA 措施状态、有效性验证、复审到期。
4. 完整基线范围和基线对象浏览。
5. ECR 影响分析、变更项、分支和新基线。
6. 导出审计和 PPAP 真实打包。

### 第三阶段：提升效率

1. 项目复制和模板复制。
2. 工序字典、4M1E 原因库、反应计划库、SOD 准则库。
3. DFMEA-DVP&R 和 PFMEA-CP 缺口视图。
4. PFD 拖拽、版本差异和下游通知。
5. SPC Excel 导入、完整判异和历史数据集。
6. MSA ANOVA、检具维护和校准预警。
7. 甘特图、报表中心、PDF、多语言。

## 19. 一句话总结

当前项目已经把“按特性贯通 APQP / FMEA / CP / SPC / MSA / PPAP”的产品方向做成了可演示原型，核心数据模型和大多数页面入口已经具备；但真实生产落地前，最需要一次性决定的是**权限与审批、项目初始化、CharLink 维护、CP 到 SPC 的生成、ECR 影响分析、完整基线和真实 PPAP 包**这七件事。
