# MSA 模拟 → 研究 → 导出 数据链核对 v1.0（2026-11-05）

- **对象**：`resistor-qms` v1.3.0，MSA GR&R 模拟数据与 Word/Excel 导出
- **方式**：真实服务 + 临时数据库（`tests/msa-export-chain.js`），模拟 10 件 × 3 人 × 3 次，保存研究后导出 XLSX 并逐格回读比对
- **结论**：数据链一致；本轮新增“零件真实值（模拟）”行，并修正报告页 ndc 显示口径

---

## 1. 数据链核对结果

| 环节 | 核对内容 | 结果 |
|---|---|---|
| 模拟 | `/api/msa/simulate` 以特性目标值为中心、在 LSL/USL 内生成零件真实值，再叠加评价人偏倚与重复误差，并按量具分辨力取整 | ✅ |
| 保存 | `POST /api/msa` 将读数写入 `msa_study.raw_json`，本次同时保存 `part_values_json` | ✅ |
| 导出数据表 | 9 行 × 10 列读数逐格等于模拟/录入读数（90/90 一致） | ✅ |
| 导出汇总 | 每位评价人的均值行、极差行由 Excel 公式（AVERAGE / MAX-MIN）计算，公式与缓存值保留 | ✅ |
| 导出报告 | EV = R̄×K1、AV = √((X̄DIFF×K2)² − EV²/(nr))、GRR = √(EV²+AV²)、PV = Rp×K3、TV = √(GRR²+PV²)，K1/K2/K3 分别取 0.5908（3 次）/0.5231（3 人）/0.3146（10 件） | ✅ 与服务端 `computeGRR` 一致 |
| 判定 | 报告“判定”格写入结论并附带 %Tol；ndc 取整数，与 `computeGRR` 的 `floor(1.41×PV/GRR)` 口径一致 | ✅ |

> 说明：Excel 的均值/极差单元格保留公式与原始缓存值，显示格式为 `0.000`，所以单元格里看到的是 3 位小数；公式栏仍是原值，重新计算不会改变结果。

## 2. 新增：零件真实值（模拟中心值）

- 模拟接口原本只返回 `part_value_min/max`，导出时无法看到每个零件的中心值。
- 现在：
  - `msa_study` 新增 `part_values_json`；
  - `POST /api/msa` 接受 `part_values`（长度必须等于零件数，逐项数值校验）；
  - 前端只在“网格数据仍与本次模拟完全一致”时才随研究提交，手工改数或切换计划/维度后不会写入过期中心值；
  - 导出 Excel 数据收集表在“零件均值”下方新增一行 **零件真实值（模拟）**，均值列显示该组中心值的极差；
  - Word 报告“研究概况”新增“零件真实值（模拟）”一行；非模拟研究显示“该研究未记录模拟零件真实值”。
- 前端模拟结果提示框同时列出全部中心值，便于保存前核对。

## 3. 验证

```
node tests/msa-export-chain.js
msa-export-chain: 模拟→研究→导出 数据链一致（9 行 × 10 列 + 零件真实值 + 报告指标）
```

该测试已串入 `npm test`（`npm run test:msa-export` 可单独运行），断言：

1. 导出数据逐格等于模拟读数；
2. “零件真实值（模拟）”行逐格等于模拟中心值；
3. EV/AV/GRR/PV/TV 与服务端结果一致（容差 1e-4）；
4. 报告 ndc 为整数且等于判定用的 ndc；
5. 判定单元格包含 %Tol。

## 4. 注意

- 历史研究（本次改动前保存）没有 `part_values_json`，导出时该行显示“未记录模拟零件真实值”，不影响其他数据。
- 外部登记的研究（`/api/msa/external`）同样没有零件真实值，这是预期行为。
