## 未验证（并说明原因）

1. **`--lan` 模式的真实局域网暴露与中间人**：需要把服务绑到 `0.0.0.0` 并对同网段发起连接，本会话被权限策略拦截（Expose Local Services），未执行。代码事实：未加 `--lan` 时 `HOST=127.0.0.1`；加 `--lan` 时 `0.0.0.0`，且为明文 HTTP，会话 Cookie 不含 `Secure`。**部署到多机前必须自行加 TLS 前置或反向代理。**
2. **`QMS_HTTPS=1` 时 Cookie 带 `Secure` 的分支**：没有 TLS 环境可测，仅代码路径正确。
3. **`lib/infer.js`、`lib/tree.js`、`lib/structure.js` 未逐行审读**：只做了危险模式排查（无 `eval` / `new Function` / 子进程调用 / 动态 SQL）。
4. **真实浏览器点击下的单引号注入**：用 DOM 复现验证了属性不会被跳出，但没有把恶意字符串真正写进数据库再走一遍页面（需要管理员创建含单引号的交付物编号）。

## 仍存在的已知边界

- 项目成员为空时对全员开放（兼容模式），需用 `QMS_STRICT_MEMBERS=1` 收紧。
- AI 密钥以明文存 `app_setting`，会随数据库备份一起被复制；备份介质需按敏感件保管。
- `server.js`（约 1.1 万行）与 `public/app.js`（约 2.4 万行）超出 OCR 单文件上限，未被机器评审，本次安全评审是人工 + 实测为主。

`npm test` 全绿（含本次新增的安全断言）；两个 Chrome e2e 单独运行通过；模糊测试 470 组无异常。
