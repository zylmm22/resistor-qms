## 1. 已按决定落实的业务规则

| 决定项 | 实施结果 |
|---|---|
| Gate 必须按 0→5 顺序通过 | 后端校验前一 Gate 必须已通过；前端显示自动验证结果并禁用不可评审门径。 |
| CP 必须同时维护样件/试生产/量产 | 每个项目自动初始化 3 份 CP；现有项目迁移时补齐 3 阶段并复制基准 CP 行；页面增加阶段页签。 |
| CP 勾选 SPC 后需质量审核 | CP 行生成“待审核”监控项；质量工程师批准后才进入 SPC 数据导入、计算和预警。 |
| CharLink 由质量角色维护 | 新增特性关联维护页，可新增、编辑、作废；已作废关联不参与穿透和影响分析。 |
| FMEA 功能与 DFMEA 上游引用拆分 | `fmea_row.func_id` 与 `fmea_row.upstream_row_id` 独立存储，旧 `effect_ref` 仅做迁移兼容。 |
| AP=H 决定必须批准后才能发布 FMEA | FMEA 发布接口检查所有高 AP 行必须具有已批准决定和批准人；未满足时返回缺口清单。 |
| 基线必须覆盖完整对象图 | 基线覆盖项目、产品族、特性、CharLink、APQP、Gate、文档与修订、FMEA 全部节点/功能/行/措施/决定、工序、CP、监控、SPC、MSA、PPAP、模板、ECR、审批和 AP 矩阵。 |
| 基线后继续编辑需活动批准 | 已有基线后冻结新基线必须填写批准人，并写入 `activity_approval`。 |
| PPAP 必须真实 ZIP + 逐文件哈希 | 生成实际 ZIP 文件；包内包含 README、18 项证据清单、基线对象 JSON、manifest；记录逐文件哈希、manifest 哈希和 ZIP 哈希。 |
| 客户模板需字段映射且映射变更需批准 | 支持把模板单元格映射到项目/文档/FMEA/CP/SPC/MSA/PPAP 字段；保存映射时要求活动批准人；可一键填充业务数据。 |
| 审核员允许查看草稿 | 当前未限制草稿可见性；审核员角色说明已改为“可查看草稿、发布内容和历史基线”。 |
| 新项目可复制现有项目且需批准 | 支持复制交付物内容、任务状态、PFD、FMEA 结构/功能/行/措施/决定、三阶段 CP 和项目级客户模板；复制活动写入批准记录。 |

## 2. 其他已解决的未实现、未闭环与风险

### 2.1 数据与迁移

- 空库可直接初始化 38 张表。
- 补齐历史数据库增量字段，包括文档元数据、FMEA 拆分字段、监控审核字段、PPAP ZIP 字段、模板映射字段等。
- 增加 `activity_approval`、`project_doc_revision`、`export_event`、`process_dict` 等治理表。
- 增加关键索引和 FMEA `(fmea_id, fe_id, fm_id, fc_id)` 唯一约束。
- 项目删除改为事务化级联清理，覆盖 FMEA、CP、SPC、基线、文档修订、模板和审批数据。
- PFD 批量替换改为“旧工序作废 + 新工序创建”，不再直接删除被下游引用的工序。
- 新增 FMEA 唯一组合校验、行 ID 单调生成、孤儿节点/候选/功能清理。

### 2.2 项目与文档

- 新项目自动创建 67 个目录项、APQP 任务、PPAP 18 项、DFMEA/PFMEA 根结构和三阶段 CP。
- 系统模块计入阶段完成度，不再导致完成度永远达不到 100%。
- 交付物增加“提交审核 → 批准/退回”流程。
- 每次保存或批准写入修订历史，批准时版本号自动升版。
- 已批准文档再次修改时自动回到草稿，必须重新审批。
- 11 张检查表改为使用专用检查表结构，不再回退到通用表单。
- 客户模板可绑定到指定交付物编号，不会额外生成重复目录行。

### 2.3 FMEA 与闭环

- 功能管理支持正式/候选、AI 候选持久化和采用后正式建行。
- 候选采用前强制补齐 FE/FM/FC/PC/DC，避免空占位流入正式行。
- 措施增加五态和有效性验证规则；未验证或有验证标志但缺证据时不能直接成为“已完成”。
- AP=H 决定未批准时 FMEA 不能发布。
- 修复 FMEA 报告中高 AP 决定状态统计。
- 新增“闭环视图”：DFMEA → DVP&R、PFMEA → CP 缺口检查。
- AP 矩阵改为数据库查表；支持批量校对和质量批准，基线会冻结整个矩阵。

### 2.4 PFD、CP、SPC、MSA

- PFD 支持单工序新增、上下移、作废、发布校验、工装治具维护和工序字典引用。
- PFD 发布自动递增版本并记录发布人和时间。
- CP 支持三阶段、表头维护、检具、样本、频率单位、触发条件、控制方法、反应计划和 MSA 预警。
- CP 人工覆盖改为字段级 JSON 记录；自动映射只保留被人工覆盖的字段。
- SPC 监控项需审核；SPC 只消费已批准、启用的监控项。
- SPC 增加历史数据集切换、Excel 导入、重复文件哈希拦截和单边规格能力指数。
- SPC 补齐常用 8 类判异规则。
- MSA 支持检具新增和维护、动态零件/评价人/试验次数、容差百分比、12 个月复评预警和校准过期预警。

### 2.5 基线、变更与导出

- 基线可查看对象清单和单对象快照接口。
- 基线差异保持按稳定对象 ID 对齐，并修正 LSL/USL 收紧/放宽方向判断。
- ECR 支持按特性、FMEA 行、CP 行或工序做影响分析，生成距离和传播路径。
- ECR 审批后创建变更请求记录，支持“已实施”状态。
- 新增活动审批记录与审批页面。
- 每次交付物、客户模板和 PPAP ZIP 导出均记录导出人、时间、格式、基线、文件名和 SHA-256。
- 新增数据库全量备份接口和页面入口。

### 2.6 技术风险

- 当前项目改为基于请求上下文的项目 ID，不再依赖全局可变 `CUR` 导致并发串项目。
- 请求体上限调整为 20 MB，能够覆盖 12 MB Office 文件 Base64 上传。
- 文档/Template 页面改为重建视图节点，避免反复打开后事件监听器累积。
- AI 七类失效调用增加 25 秒超时。
- 增加 `npm test` 空库与端到端烟雾测试。

## 7. 本轮问题修复补充

### 7.1 工序排序

- PFD 上下移动工序后，后端同时重排 `seq` 和显示用 `step_no`。
- 工序号按 010、020、030 格式重新编号。
- 流程示意与工序明细都读取同一 `seq` 排序结果，因此移动后会同步刷新。
- 工序稳定 ID 不变，已有 FMEA/CP 引用不因排序而丢失。

### 7.2 FMEA 无法打开

- 根因是部分历史项目缺少 `fmea_header`，GET `/api/fmea` 返回“未找到 FMEA”。
- 启动迁移现在会为每个项目自动补建 DFMEA/PFMEA 表头和根结构节点。
- 已验证缺少 FMEA 的 `RES-CHIP-2026-02` 可正常打开 DFMEA 和 PFMEA。

### 7.3 自定义模板外观

- 自定义 XLSX/DOCX 模板增加统一系统外观容器和“模板内容”区块。
- 表头、标签、输入单元格、边框、圆角、字体和聚焦态统一为与内置交付物一致的视觉规范。
- 保留原模板合并单元格、列宽和行列结构。

### 7.4 CP 选择测量设备

- SPC 监控弹窗直接列出当前项目检具台账。
- 显示每个检具的最近 `%GRR`、校准日期和 GRR 状态。
- 选择后写回 CP 行的 `gauge_id`，再创建监控项，不再需要跳转 MSA 页面查询编号。

### 7.5 SPC 加载错误

- 根因是监控项没有 SPC 数据集时，后端把单条查询结果当成数组执行 `[0]`。
- 已改为数组查询并安全返回 `latest = null`。
- 前端增加空数据保护；未导入数据时显示正常空态，不再报“Cannot read properties of undefined”。

### 7.6 控制计划特性来源

- 新增“关联特性”弹窗，可在产品特性和过程特性之间选择。
- CP 表显示特性来源：`来源 PFMEA`、`人工关联`、`人工覆盖 PFMEA`。
- 过程特性通过 CharLink 显示其关联产品特性。
- PFMEA 行增加可选“关联过程特性”字段。
- CP 自动映射优先使用 PFMEA 的过程特性；未指定过程特性时回退到产品特性。
- 自动映射会同时写入 CP 的特性、规范、FMEA 行来源和上游版本。

### 7.7 MSA 行数逻辑

- 根因是前端把正确的 `9 行 × 10 列` 错误乘成了 90 行。
- 现在按 `评价人 × 试验次数 = 行数`，`零件数 = 每行列数` 校验。
- 默认配置为 3 人 × 3 次 = 9 行，每行 10 个零件值，共 90 个数据点。
- 页面增加动态提示：需要多少行、多少列、多少数据点。
- MSA 计算结果不再在 1.4 秒后自动刷新消失。
